# Change Management

## Small implementation change

Implement within the active phase, add tests, and update local documentation when behavior changes.

## Requirement change

Update the stable requirement, acceptance criteria, roadmap mapping, test mapping, and changelog before implementation.

## Architecture change

Create or update an ADR. An accepted ADR changes only when a documented revisit condition is met.

## Scope change

Update product scope and out-of-scope documentation, requirements, roadmap, validation assumptions, and tests before implementation.

Never allow a code-only change to silently alter product behavior or architecture.
